# ניתוח מודעות מהעיתון — דוגמה ידנית

התיקייה `עיתון_פותחים_שבוע_טז_אלול/` בשורש הריפו מכילה 48 עמודי עיתון קהילתי סרוקים (`pages/`) ו-166 מודעות
בודדות שנחתכו מהם (`ads/`).

## מה נעשה כאן, ולמה ידני ולא אוטומטי

הכלי לניתוח מודעת רפרנס (`POST /clients/:id/reference-ads` להעלאה, ואז `POST /documents/:id/decompose`,
המבוסס על `pipeline.decomposeReferenceAd` — ראו DECISIONS.md D40) **קיים ועובד**, ונבדק ב-`GEMINI_MOCK=1`
(`server/test/hierarchy.test.js`). אבל הרצה אמיתית שלו על 166 המודעות דורשת מפתח Gemini אמיתי, וסביבת הבנייה
הזו חסומה לגישה ל-Google (כמו כל שאר קריאות ה-Gemini האמיתיות בפרויקט, D17) — כך שלא ניתן היה להריץ את הכלי
בפועל מתוך הסשן הזה.

כדי בכל זאת "לעבור על המודעות ולהסביר איך בונים כל קבוצת מודעות בקונספטה" (כפי שהתבקש), שש דוגמאות מייצגות
נותחו **ידנית** למטה, באותו פורמט בדיוק שהכלי האמיתי מייצר (`archetype`/`summary_he`/`elements`/`panels`/
`textLines`/`concept_md`). זו לא הדגמה מזויפת של הפלט — זו בדיוק אותה סכימה, רק שהניתוח נעשה בעין אנושית
במקום בקריאת API. **מי שירצה להריץ את זה אוטומטית על כל 166 המודעות**, צריך רק להזין מפתח Gemini בהגדרות
ולעלות כל מודעה תחת לקוח מתאים ("ניתוח קונספט" בטאב "מודעות רפרנס") — הכלי כבר עובד מקצה לקצה.

## למה בכלל היה צריך לבנות מצב חדש (ולא רק לנתח)

הבדיקה הידנית הזו היא מה שחשף שרוב המודעות בעיתון הזה **אינן** מודעות צילום-מוצר פוטוריאליסטי (מה שקונספטה
ידעה לבנות לפני v3) אלא מודעות **גרפיות-טיפוגרפיות**: פאנל צבע, כותרת גדולה, רשימת בולטים או מחירים, לוגו
ופרטי קשר בתחתית. לכן לפני שאפשר היה "להסביר איך בונים" את רוב המודעות האלה, היה צריך קודם לבנות מצב שבו
זה בכלל אפשרי — ראו D39 (`brief.adStyle`, `plan.panels`, `mandatory.lines`). שתי הדוגמאות היחידות למטה
שכן מתאימות למנוע הצילום המקורי הן #4 וחלקית #5.
